# 密语（codebook）UI 需求规范

> 文档状态：v1 UI 重构基线
>
> 适用平台：浏览器、Android WebView
>
> 目标视口：360×640 起，重点验收 390×844、1280×900
>
> 核心原则：私密、安静、清晰、可信，不使用“黑客终端”式视觉

## 0. 设计参考与落地原则

- 交互设计参考：`/mnt/e/project/study/workbuddy/ui/codebook/design-review/`。
- 最新可运行参考以 2026-07-31 更新的 `index.html` 与 `screens.js` 为准；参考目录中的 `design-system.md` 若仍保留旧靛蓝色值，不作为颜色权威来源。
- 工程实现以本文件、现有产品功能和真实数据状态为准；参考稿不完整或与功能冲突时，优先保证加密流程、可访问性和 Android WebView 行为。
- 参考稿中的森林夜色、薄荷白、薄荷绿、浅天蓝、珊瑚红和“密”字印章已转化为全局设计令牌，页面不得自行引入冲突的品牌色。

## 1. 设计目标

1. 用户在 3 秒内理解当前页面、主要动作和敏感信息状态。
2. 保险箱内容优先于装饰；任何装饰不得降低密码、TOTP、警告和错误信息的可读性。
3. 移动端保持单手可用，桌面端充分利用宽度但不把表单无限拉长。
4. 明文密码、TOTP、备份和删除操作必须有明确的风险语义，不依赖颜色单独表达。
5. 浅色与深色主题拥有同等完成度，并遵循系统主题与用户选择。
6. 所有页面共享一致的信息层级、间距、按钮、表单、空状态和反馈语言。

## 2. 品牌与视觉语言

### 2.1 品牌关键词

- 密语：克制、私密、安静守护。
- Codebook：有结构的密码簿、索引、可查找的安全档案。
- 避免：荧光绿代码雨、夸张霓虹、军事化警报、过度玻璃拟态。

### 2.2 视觉方向

- 采用“加密档案册”概念：柔和纸张层次、清晰索引、精细边框和少量印章式品牌元素。
- 主色为清透薄荷绿，天蓝用于品牌渐变与少量强调；安全成功状态使用自然绿，风险使用珊瑚红，警告使用琥珀色。
- 深色背景采用“森林夜色”，浅色背景采用“薄荷白”；背景允许低对比度薄荷、天蓝和暖阳柔光，但正文区域必须保持稳定纯净。
- 圆角中等，不使用过度胶囊化；卡片强调分组，不让每一行都变成独立浮层。

### 2.3 品牌标识

- 主标识为方圆结合的“密”字印章。
- 锁屏和引导页可展示完整品牌标识；业务页只保留小尺寸标识或图标。
- 中文产品名固定为“密语”，工程英文名固定为 `codebook`。

## 3. 设计令牌

### 3.1 色彩

| 语义 | 深色主题 | 浅色主题 |
|---|---|---|
| 页面背景 | 森林夜色 `#0f1614` | 薄荷白 `#f0f9f6` |
| 一级表面 | 半透明深森林绿 | 半透明纯白 |
| 二级表面 | 半透明墨绿 | 淡薄荷绿 |
| 主色 | 薄荷绿 `#2dd4bf` | 自然薄荷 `#14b8a6` |
| 品牌辅色 | 天蓝 `#7dd3fc` | 天蓝 `#38bdf8` |
| 安全/成功 | 青绿色 | 深青绿 |
| 危险 | 珊瑚红 | 深红 |
| 警告 | 琥珀黄 | 深琥珀 |
| 主文字 | 近白 | 墨蓝黑 |
| 次文字 | 冷灰 | 中灰蓝 |

要求：正文对背景至少达到 WCAG AA；禁用态仍需可辨识，不能只降低到不可读透明度。

### 3.2 字体

- 中文优先：`PingFang SC`、`Microsoft YaHei`、系统无衬线字体。
- 数字、密码、TOTP 和密钥使用等宽字体。
- 页面标题 28–36px；区块标题 16–18px；正文 14–16px；辅助信息不小于 12px。
- 标题紧凑，正文行高 1.55–1.7，长备注必须易读。

### 3.3 间距与尺寸

- 基础间距单位 4px；常用间距 8、12、16、20、24、32、40px。
- 移动端页面左右安全边距 16px；桌面端内容区左右边距至少 28px。
- 可点击目标最小 44×44px，主按钮高度 48–52px。
- 表单输入高度 48px，文本域最小高度 112px。
- 卡片圆角 18–24px；输入框圆角 12–14px。

### 3.4 阴影与动效

- 阴影只用于页面层级、浮动导航和对话框，不用于每一行列表。
- 页面进入、弹层和悬停动效为 150–240ms。
- 遵守 `prefers-reduced-motion`，减少动效时取消位移和缩放。

## 4. 响应式框架

### 4.1 移动端（小于 760px）

- 主导航固定在底部，仅显示“保险箱”和“设置”。
- 页面使用单列；表单多列布局自动折叠。
- 页面主操作放在右上角或底部安全区域附近。
- 长列表与长表单只有页面主体滚动，弹层内部独立滚动。

### 4.2 桌面端（760px 及以上）

- 主导航转换为左侧固定侧栏，显示品牌、导航项与本地安全说明。
- 内容区域最大宽度约 1120px；普通设置/表单最大宽度约 920px。
- 保险箱列表可使用两列卡片；详情页可使用主内容 + 辅助信息双列。
- 页面标题与操作按钮保持在同一视觉基线。

## 5. 全局组件要求

### 5.1 应用导航

- 当前导航项必须同时通过颜色、背景和图标状态表达。
- 导航不遮挡页面正文，适配安全区。
- 锁屏、引导、详情、编辑和二级设置页不显示主导航。

### 5.2 页面标题栏

- 一级页：标题、说明、主要动作。
- 二级页：返回图标、标题、可选的右侧动作。
- 编辑页标题栏可粘性吸顶，但不得遮挡系统安全区。

### 5.3 按钮

- Primary：当前页面唯一最主要动作。
- Secondary：次要但常用动作。
- Ghost：返回、取消、弱操作。
- Danger：删除、明文导出、清空数据。
- 图标按钮必须提供 `aria-label`。

### 5.4 表单

- 标签始终可见，不用 placeholder 替代字段名称。
- 必填字段明确标注；帮助文本与错误文本紧邻字段。
- 密码字段提供显示/隐藏；敏感内容默认隐藏。
- Checkbox/Switch 使用可点击整行，状态不依赖颜色。
- 表单分区必须用标题和说明表达用途。

### 5.5 卡片和列表

- 卡片用于逻辑分区，列表行用于同类数据。
- 列表行提供明显的主文本、次文本、状态和点击反馈。
- 空状态必须解释原因并提供下一步动作。

### 5.6 状态反馈

- Loading：按钮内显示进行中状态并禁用重复提交。
- Empty：图标、标题、解释和可选主动作。
- Error：就近显示，可恢复错误提供重试。
- Success：Toast 可用于轻量反馈；关键导入结果需保留在页面中。
- Dialog：危险操作说明影响范围，确认按钮使用明确动词。

## 6. 页面需求

### 6.1 引导页

- 左侧/上方说明本地加密、无账号、无云同步三个核心特性。
- 6 位数字主 PIN 创建表单为视觉焦点。
- 显示 0–6 位输入进度，使用移动端数字键盘。
- 明确说明主 PIN 无法找回。
- 移动端为单卡片；桌面端为品牌说明 + 表单双栏。

### 6.2 锁屏

- 显示安静、简洁的品牌区与最后一道安全提示。
- Android 已启用时优先展示指纹/人脸解锁，取消后自然回退主 PIN。
- 主 PIN 输入和“解锁”作为稳定备用操作；旧保险箱继续展示原主密码输入。
- 错误 PIN/密码在输入区附近显示。
- 旧格式重置和致命错误使用独立警告状态，不与正常解锁混排。

### 6.3 保险箱列表

- 顶部展示条目总数、收藏数和启用 2FA 的数量。
- 搜索框始终可见，带搜索图标和清除能力。
- 分类筛选横向滚动，颜色点与名称同时呈现。
- 条目卡展示首字母、标题、账号/网址、分类、收藏和 2FA 状态。
- 空保险箱提供“新建第一条记录”；搜索无结果提供清除筛选提示。

### 6.4 条目详情

- 顶部摘要展示标题、分类、收藏和最近使用状态。
- 登录信息、TOTP、自定义字段、邮箱关联和记录信息清晰分区。
- 可复制值拥有一致的复制 affordance；网址拥有打开动作。
- 密码默认遮罩且点击复制时不在 UI 中泄露。
- TOTP 显示剩余时间进度和复制动作。
- 编辑为主要动作，删除放入危险区域。

### 6.5 新建/编辑条目

- 表单按“基本信息、自定义字段、2FA、邮箱关联”分区。
- 桌面端基本信息允许双列，长字段保持整行。
- 保存按钮吸顶可达；未保存离开继续二次确认。
- 可重复项目具备顺序、删除和空状态。
- 扫码是添加 TOTP 的首选动作，URI 和手工输入为次级方式。

### 6.6 分类管理

- 新建/编辑表单与分类列表在桌面端双列，移动端上下排列。
- 分类颜色提供预览和颜色选择。
- 排序、编辑、删除动作尺寸一致；删除说明不会删除条目。

### 6.7 设置

- 分为“保险箱管理、安全与隐私、显示、危险区域、关于”。
- 每项提供名称和简短说明，当前值右对齐。
- Android 屏幕保护状态显式显示。
- Android 生物识别状态显式显示，可启用或关闭，并说明不可用原因。
- “立即锁定”突出但不使用危险色；“清空本地数据”单独位于危险区域。

### 6.8 导入与导出

- 加密备份作为推荐方式，拥有最高视觉优先级。
- CSV 明文交换使用危险色和永久可见警告。
- 导入区域展示已选文件、格式预览和统计结果。
- 加密导入与 CSV 导入使用不同按钮语义，避免误操作。

### 6.9 修改主 PIN

- 解释“只重新封装 DEK”的用户含义：快速修改，不重写全部条目。
- 三个凭据字段顺序明确，新 PIN 严格限制为 6 位数字。
- 突出旧备份仍由导出时的原 PIN/密码保护。

### 6.10 扫码与 TOTP 确认

- 扫描阶段显示取景框、状态和隐私说明。
- 确认阶段展示遮罩后的密钥与全部 TOTP 参数。
- 取消必须始终可达；后台、锁定和返回键必须停止相机。

## 7. 可访问性与隐私

- 所有交互元素支持键盘操作和清晰焦点环。
- 图标按钮必须有文本标签或 `aria-label`。
- 表单使用语义化 `form`、`label`、`button`。
- 错误、成功、警告不得只依赖颜色。
- 不在 DOM 中展示已遮罩密码的明文副本。
- 支持 200% 字体缩放时主要流程可用，无横向页面滚动。

## 8. 验收矩阵

| 范围 | 验收标准 |
|---|---|
| 390×844 | 所有页面无横向溢出，底部导航不遮挡内容，主操作可达 |
| 1280×900 | 左侧导航生效，内容宽度舒适，列表/详情合理利用双列 |
| 深色/浅色 | 文字、边框、输入框、对话框和危险状态均清晰可读 |
| 键盘 | Tab 顺序合理，焦点可见，Enter 可提交主要表单 |
| 状态 | 空、加载、错误、成功、危险确认均有明确 UI |
| 功能回归 | 原有加密、CRUD、TOTP、分类、导入导出和设置行为不改变 |
| 浏览器质量 | 控制台 0 error、0 warning；关键页面保留截图证据 |
